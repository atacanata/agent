# UX-001: Runner UX (Stage B)

## Overview
Runner arayüzü, bir projeyi seçip Stage A/B/C checkpoint akışını izlemek, runbook artefaktlarını görmek ve her checkpoint sonunda "Approve to proceed" kapısını yönetmek için tasarlanır.

## Primary Flows
1. Project Selection
- User opens runner.
- System loads project list.
- User selects a project to view runs and current checkpoint status.

2. Checkpoint A/B/C (per run)
- User opens a run and sees checkpoint timeline (A, B, C).
- Each checkpoint shows status and required outputs.
- On completion, user triggers "Approve to proceed" gate.
- If approved, next checkpoint unlocks; if rejected, checkpoint returns to "Changes requested".

3. Runbook Viewer
- From a run, user opens the runbook viewer.
- Viewer lists artifacts (ci/test/diff/review) with timestamps.
- User can open/download artifacts.

4. Approve to Proceed Gate
- Approver reviews required artifacts and checklist.
- Approver submits approval with optional note.
- System records approval and unlocks next checkpoint.

## Screens
### Project Selection
- Purpose: Choose a project to manage.
- Primary actions: Select project, refresh list.
- Content: Project name, last run status, last updated.

States
- Loading: list skeleton.
- Empty: "No projects found" with refresh.
- Error: "Failed to load projects" with retry.

### Checkpoint A/B/C
- Purpose: Track progress for Stage A/B/C in a run.
- Primary actions: Open required docs, open runbook, request approval.
- Content: Timeline with status badges and gate status.

States
- Not started: checklist empty, gate disabled.
- In progress: checklist partial, gate disabled.
- Ready for approval: checklist complete, gate enabled.
- Approved: locked with approval summary.
- Changes requested: shows feedback and rework required.
- Blocked: missing runbook artifacts or prerequisites.

Error cases
- Run not found.
- Stage artifacts missing (e.g., no `ci_*.log`).
- Gate rejected due to incomplete checklist.

### Runbook Viewer
- Purpose: Inspect run artifacts.
- Primary actions: View artifact, download artifact, filter by type.
- Content: Artifact list (name, size, updated time), preview panel.

States
- Loading: artifact list skeleton.
- Empty: "No artifacts available".
- Error: "Failed to load artifacts" with retry.

Error cases
- Artifact not found.
- Artifact download failed.

### Approve to Proceed
- Purpose: Enforce explicit gate between checkpoints.
- Primary actions: Approve, request changes.
- Required inputs: Approver name (or identity), optional notes.

States
- Pending: awaiting decision.
- Approved: approval recorded and next checkpoint unlocked.
- Rejected: changes requested, checkpoint remains locked.

Error cases
- Unauthorized or missing approver.
- Approval attempted before checklist completion.
- Concurrent approval conflict (already approved by another user).

## Status Model
- Run status: `queued`, `running`, `blocked`, `failed`, `succeeded`.
- Checkpoint status: `not_started`, `in_progress`, `ready_for_approval`, `approved`, `changes_requested`, `blocked`.

## Non-Goals (Stage B)
- No code generation or UI implementation.
- No external integrations beyond repository docs/runbook artifacts.
